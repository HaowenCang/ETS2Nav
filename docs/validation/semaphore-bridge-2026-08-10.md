# semaphore-bridge 自研信号灯数据源验证（2026-08-10）

状态：✅ **验证通过——零外部依赖的信号灯数据源达成**

## 数据链路

```
ETS2 游戏进程（semaphore-bridge.dll，自研）
   │  启动时特征扫描定位信号灯数组（48B/灯：pos+cx/cy+quat+type+time+state+id）
   │  10Hz 读取 → 共享内存 Local\ETS2NavSemaphore（magic+version+sequence+count+N×48B）
   ▼
sem-probe / 导航核心（任何进程可读）
```

## 验证结果

| 项 | 结果 |
|---|---|
| 启动卡死（v1 问题） | ✅ 修复：延迟扫描（frame_start 就绪）+ 低优先级线程 + 重扫节流 |
| 误定位（v2 问题） | ✅ 修复：槽验证加强（time≤60/pos 非零/cx/cy≠-1/四元数归一化）+ 候选列表 + 连续槽锁定 |
| 数据正确性 | ✅ 与 ETS2LA 共享内存对照一致（pos/id/状态互补/time 递减速率） |
| 性能 | 10Hz 读取 + 定位后零扫描开销；扫描仅启动/重载时低优先级执行 |

## 意义

- **P0-B 完整闭环**：自研插件直接提供 state + time_remaining（精确数据，非外推）——倒计时功能数据源自主化
- 不依赖 ETS2LA（对照仅用于开发验证）/ 无视觉开销
- 与 ETS2LA 通道的定位：ETS2LA 仅作开发期对照工具；自研通道为产品数据源

## 已知限制与后续

- count 截断：连续槽统计在首个空槽处截断（当前路口 4 灯完整；长数组中间有空槽时后续灯丢失）→ 后续改进为"容忍间隙统计"（连续 4 空槽才截断）
- 数组基址随游戏启动变化：插件启动时自动扫描定位（已验证）；游戏重载（timer_restart）自动重扫
- 游戏版本更新可能改变结构：需要时重新反查验证（工具链已备：memscan-probe/RawDump）
