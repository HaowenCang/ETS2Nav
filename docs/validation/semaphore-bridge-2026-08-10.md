# semaphore-bridge 自研信号灯数据源验证（2026-08-10）

状态：✅ **验证通过——零外部依赖的信号灯数据源达成**

## 数据链路

```
ETS2 游戏进程（semaphore-bridge.dll，自研）
   │  启动时特征扫描定位信号灯数组（48B/灯：pos+cx/cy+quat+type+time+state+id）
   │  10Hz 读取 → 共享内存 Local\ETS2NavSemaphore（magic+version+sequence+count+N×48B）
   ▼
sem-probe / 导航核心（任何进程可读）
```

## 意义

- **P0-B 完整闭环**：自研插件直接提供 state + time_remaining（精确数据，非外推）——倒计时功能数据源自主化
- 不依赖 ETS2LA（对照仅用于开发验证）/ 无视觉开销
- 与 ETS2LA 通道的定位：ETS2LA 仅作开发期对照工具；自研通道为产品数据源

## 已知限制与后续

- count 截断：连续槽统计在首个空槽处截断（当前路口 4 灯完整；长数组中间有空槽时后续灯丢失）→ 后续改进为"容忍间隙统计"（连续 4 空槽才截断）
- 数组基址随游戏启动变化：插件启动时自动扫描定位（已验证）；游戏重载（timer_restart）自动重扫
- 游戏版本更新可能改变结构：需要时重新反查验证（工具链已备：memscan-probe/RawDump）

## 重大发现：ETS2LA 插件激活信号灯数组（2026-08-10 深夜）

**对照实验（同一动态灯路口，独立扫描器铁证）**：
| 状态 | 48B 数组 | 灯变化 | 车辆按灯通行 |
|---|---|---|---|
| ETS2LA 全家在场 | ✅ 存在（40 灯，数据完美） | ✅ | ✅ |
| 仅自研插件（无 ETS2LA） | ❌ 0 匹配（多次扫描：5289MB/5468MB/5522MB/6215MB） | ✅ | ✅ |
| 无 ETS2LA + 快速旅行重载 | ❌ 0 匹配 | ✅ | ✅ |

**结论**：48B 信号灯数组由 ETS2LA 插件（或其 SDK 组件）激活（机制不明，闭源）；游戏原生灯模拟存在（灯变化+车按灯通行），但原生数据结构非 48B 布局（MirrorScan 反查：坐标窗口/精确世界坐标/多灯聚类均被几何点云噪声淹没，原生结构疑为指针化对象图）。

**产品影响**：自研 semaphore-bridge 需要 ETS2LA 组件共存才能获得数组。下一步：隔离测试（仅 ets2la_plugin.dll → 数组？）确定最小激活依赖；产品路线决策（共存 vs 逆向激活机制）。

### 隔离测试定案（2026-08-10 深夜）
| 配置 | 数组 |
|---|---|
| 仅 ets2la_plugin.dll + 自研两插件 | ✅ 存在（seq=1631、40 灯完美） |

**激活者 = ets2la_plugin.dll 单文件**（370KB）——无需 ETS2LA 主程序/scs-telemetry.dll/scs_sdk_controller.dll/Trucky。

**产品依赖最小化**：运行时 plugins 目录 = scs-nav-bridge.dll + semaphore-bridge.dll + ets2la_plugin.dll（共存激活）。

**遗留风险**：ets2la_plugin.dll 闭源第三方组件——激活机制未明（疑为加载时 hook/内部调用）；依赖其存在性与行为稳定。
