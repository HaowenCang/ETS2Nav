## 审计项 1：ALT/CH "登记不做"判定链 —— FIXED（结论成立），伴随 MAJOR×2 数据引用缺陷

### 1.1 判定链本身成立（FIXED）

- **计划授权**：PLAN-P3plus.md §2 A4 原文"若 benchmark 显示必要性则实现，否则登记为'目标已达成，不做'（§62 是验收标准而非无条件工作项）"——报告 1.2 的行为与计划原文完全一致。审计任务书引用的"§62 非无条件工作项"确为计划原文。
- **基线支撑**：路线 p99 0.378ms 有记录（P3-09 报告表，Europe v4）。按 v0.2 §62 真实口径（Routing 典型 <1s、极端 <2s）计算，裕度 2646× / 3317×，**超 1000× 成立**。Rerouting 实测 <0.5ms（P2-19）vs §62 ≈1s 目标亦达标。ALT/CH 收益（对已达标指标再加速）与成本（~2 周工程）不匹配的论证合理。
- **结论方向**：即使考虑图规模随 DLC 增长（当前 5.6M 节点），需 1000 倍增长才会触及阈值——"不做"判定鲁棒。

## 审计项 2：增量编译指纹方案 —— 部分（实现正确、additive 兼容），伴随 MAJOR×3

### 2.1 实现正确性与向后兼容（FIXED）

- **additive 零 schema 变更成立（实测）**：DatasetWriter 增加可空 `content_fingerprint`；Rust 侧 check_manifest 用 serde_json::Value 按字段名取值、未知字段忽略（nav-core/crates/nav-dataset/src/lib.rs:156 起），dataset_version 保持 2；旧 dataset 缺字段 → stored=null → CHANGED（安全方向）。新旧双向兼容均成立。
- **size+mtime 充分性论证成立**：指纹 = exe FileVersion + 全部 archives(name,size,mtime UTC ticks) + DLC 集合 → SHA-256，枚举确定性（Name 排序 + Distinct）。Steam 更新必改 mtime，game_version 兜底；漏报需"版本不变+size 不变+mtime 不变+内容变"（仅防御性拷贝工具场景），误报方向（touch 即 CHANGED）只触发一次重建提示，代价可接受。与 P1 §11 建议输入（version/archive list/sizes/timestamps/DLC）一致（relevant archive hashes 未做，已登记）。
- **CHANGED 路径实测复现**：`map-inspector --check-fingerprint --install <安装目录> --dataset data/europe-v4` → `FINGERPRINT CHANGED stored=none cur=fa3ef5bb...`，exit=1（本审计复现；C# 编译 0 错误）。
