# TL-01 Clock Domain 实验结果（2026-08-09）

状态：✅ 结论确定（数据：signal-lab-data/events_20260809-211411.csv + samples 同会话）

## 实验设置

- 一个城市信号灯路口，连续记录 2 个完整周期（8 个相位转换事件）
- 按键：1=变绿（R2G）、2=变红（G2R）、3=黄灯/其他（OTHER）
- 同步记录：Windows 时钟（wall）、simulation_time（sim）、paused_simulation_time、game.time、scale

## 数据

**全部 7 个间隔的实测倍率 = 1.000（±0.7%）**，而同期 game.time 以 3 倍速前进（scale=3.000）。

## 结论

1. **信号灯由 simulation_time 时钟驱动，interval 的"秒" = 真实秒（1:1，无需倍率换算）**。
   - 排除 game.time 驱动：若由游戏时钟驱动，倍率应 = scale = 3.0，且 60s 周期的 R2G 间隔应为 20 真实秒（实测 59.55 真实秒）。
   - 社区"城市 1:3 压缩信号灯"的说法**不成立**（至少对该场景）；v0.2 §28 的"证据不足"已由本实验解决。
2. **周期 ≈ 59.5s**，与 profile `tr_sem_prof.cr_2x1_turn` 等 (15,2,41,2) 的 60s 周期吻合（0.8% 误差，含人工按键延迟）。
3. 段长（实测 绿≈23.7/黄≈2.8/红≈32.3）与 (15,2,41,2) 名义值不符——**原因待查**：可能被测路口使用其他 profile、或人工按键时机偏差、或段长语义（黄灯 2.8s 实测 vs 2s 名义，红灯 32.3 vs 41 差异大，需精确相位检测复查）。

## 对 P0-B 的影响

- **倒计时计算无需倍率换算**：phase(t) 直接用 simulation_time（真实秒）与 profile interval（视为真实秒）计算。
- 信号灯计时基准 = simulation_time → **相位锚定 = 灯组加载时刻 + simulation_time 偏移**（指向 H2 局部计时器，TL-02 待多次会话确认）。
- simulation_time 在读档/快速旅行时可能重置（官方 timer_restart flag）——TL-04 需验证重置时信号灯是否同步重置。
