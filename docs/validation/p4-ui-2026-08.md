- ping/pong + close 帧处理

### 5. 目的地→导航链路（§60 关键闭环）
POST /api/route 同步设置 session 目的地（pending_dest 通道）→ 数据源线程消费 →

偏航→重规划→到达状态机由 P2-17 单测覆盖（session_reaches_arrived_along_route 等）。

## 三、技术要点与修复记录

- **Rc→Arc（session API）**：服务器跨线程共享只读图——`NavigationSession` graph/spatial
  由 `std::rc::Rc` 改 `std::sync::Arc`（additive，测试不变）。
- **NavigationSnapshot 扩展**：新增 `speed_kmh`/`map_limit_kmh`（UI 速度/限速卡片输入，
  提醒收集块已有 matched_limit 复用）。
- **read_http_head 同包 bug**：head 与 body 同包到达时 body 丢失（字节字面量曾含真实 CR
  致 `\r\n\r\n` 永不匹配）→ 重写（显式 `[13,10,13,10]` 匹配 + 剩余字节返回 + 补读），
  单测 `read_http_head_same_packet` 锁定。
- **HTTP keep-alive 差异**：curl 一次性发送 vs 分包——补读路径覆盖两者。
- **坐标系（§59）**：ETS2 米制 → 渲染层 `lng=x/111320, lat=z/111320`（与瓦片生成一致）。
- **MapLibre 本地化**：CDN（unpkg）被浏览器 tracking prevention 阻断 → vendor/ 本地化。
- **style load 时序**：图层/数据源操作移入 `map.on('load')`，DOM 卡片更新不依赖地图就绪。
